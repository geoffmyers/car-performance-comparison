# CLAUDE.md - Car Performance Comparison

Development guidelines and project context for AI assistants.

## Project Overview

A Next.js web application displaying car performance data from multiple sources. Uses SQLite for server-side data storage and TanStack Table for the frontend data grid.

## Quick Commands

```bash
# Development
npm run dev          # Start dev server at localhost:3000
npm run build        # Production build
npm run lint         # ESLint check

# ETL Pipeline (from project root)
python -m etl.cli run        # Full ETL pipeline
python -m etl.cli run -v     # Verbose output
python -m etl.cli status     # Show pipeline status
```

## Architecture

### Data Flow

1. **Source Data** (`public/data/<source>/`) - Raw CSV/HTML files from various sources
2. **ETL Pipeline** (`etl/`) - Python parsers normalize and merge data
3. **SQLite Database** (`public/data/car-performance-data.db`) - Unified storage
4. **API Routes** (`src/app/api/cars/`) - Server-side pagination and filtering
5. **Frontend** (`src/components/DataTable.tsx`) - TanStack Table display

### Key Files

| File | Purpose |
|------|---------|
| `src/lib/db.ts` | SQLite database service, query building |
| `src/lib/schemas.ts` | Zod validation for API parameters |
| `src/hooks/useCarsApi.ts` | React hook for API data fetching |
| `src/components/DataTable.tsx` | Main data table component |
| `src/types/car.ts` | Auto-generated TypeScript types |
| `etl/cli.py` | ETL command-line interface |
| `etl/config/sources.yaml` | Data source configuration |
| `etl/config/schema.yaml` | Field definitions and constraints |
| `etl/parsers/base.py` | Base parser class |
| `etl/core/merger.py` | Multi-source data merging |

## Data Requirements

Records are included in the API if they have:
- `manufacturer` (non-empty)
- `model` (non-empty)
- `year` (non-empty)

This filter is defined in `src/lib/db.ts` as `REQUIRED_FIELD_CONDITIONS`.

## ETL Pipeline

### Adding a New Parser

1. Create parser file: `etl/parsers/<source>/<parser_name>.py`
2. Inherit from `BaseParser`:

```python
from etl.parsers.base import BaseParser, CarRecord, ParseResult

class MyParser(BaseParser):
    SOURCE_NAME = "My Source"
    SUPPORTED_FORMATS = ["csv"]

    def can_parse(self, file_path: Path) -> bool:
        return file_path.suffix == ".csv"

    def parse_file(self, file_path: Path) -> ParseResult:
        # Implementation
        pass
```

3. Add to `etl/config/sources.yaml`
4. Register in `etl/parsers/<source>/__init__.py`

### Parser Utilities

The base parser provides helper methods:
- `_parse_car_name(text)` - Split "Make Model" into tuple
- `_normalize_manufacturer(name)` - Standardize manufacturer names
- `_get_country(manufacturer)` - Get country code
- `_parse_time(value)` - Parse "mm:ss.s" or seconds
- `_parse_speed(value)` - Parse speed with unit detection
- `_parse_power(value)` - Parse power with unit detection
- `_clean_model_name(model)` - Remove test suffixes, HTML entities

## API Endpoints

### GET /api/cars

Query parameters (all optional):
- `page` - Page number (default: 1)
- `pageSize` - Records per page (default: 50, max: 100)
- `sortBy` - Column name to sort
- `sortOrder` - "asc" or "desc"
- `manufacturer` - Filter by manufacturer
- `country` - Filter by country code (US, DE, JP, etc.)
- `yearMin`, `yearMax` - Year range filter
- `search` - Full-text search on manufacturer/model

### GET /api/cars/meta

Returns filter options: manufacturers, countries, year range, total count.

## Database Schema

The SQLite database has a single `cars` table with columns defined in `etl/config/schema.yaml`. Key columns:

- Identification: `manufacturer`, `model`, `year`, `country`, `propulsion`
- Performance: `0_60_mph_sec`, `quarter_mile_sec`, `top_speed_mph`
- Lap times: `nurburgring_lap_sec`, `top_gear_lap_sec`, `lightning_lap_sec`
- Specs: `power_hp`, `torque`, `curb_weight_lb`

## Common Tasks

### Fixing Data Issues

1. For parser bugs affecting future data: Fix the parser in `etl/parsers/`
2. For existing data: Run ETL (`python -m etl.cli run`) or directly update the database
3. The merger preserves existing data, so manual fixes may be needed for already-processed records

### Updating Type Definitions

Types in `src/types/car.ts` are auto-generated by the ETL pipeline. To regenerate:

```bash
python -m etl.cli run
```

This reads `etl/config/schema.yaml` and outputs TypeScript types.

### Database Queries

Direct database access for debugging:

```bash
sqlite3 public/data/car-performance-data.db

# Count records
SELECT COUNT(*) FROM cars;

# Find duplicates
SELECT year, manufacturer, model, COUNT(*)
FROM cars
GROUP BY year, manufacturer, model
HAVING COUNT(*) > 1;

# Search for specific records
SELECT * FROM cars WHERE model LIKE '%Corvette%' LIMIT 10;
```

## Gotchas

- This project is published to GitHub (`geoffmyers/car-performance-comparison`) as a snapshot.
  Each publish appends one commit to the public history. Publish with:
  `scripts/publish-subtree-snapshot.sh --prefix=nextjs-projects/car-performance-comparison --publish`
  Exclusions and GitHub metadata are declared in `scripts/subtree-publish.json`.
- **NEVER run `git subtree push` or `git subtree split`.** A raw split has twice
  pushed the entire mono-repo history — and the secrets in it — to a public remote
  (see `docs/security/2026-02-04-` and `2026-05-12-credential-leak-audit.md`). A
  pre-push hook refuses it.
